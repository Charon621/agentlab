# AgentLab 项目报告

> 本文档面向评审者与面试官，从问题、设计取舍与验证策略的角度梳理项目；
> 操作说明见 [README](../README.md)，各阶段验收记录见 [验收与恢复_2026-10-15](验收与恢复_2026-10-15.md)。

## 1. 选题背景与问题定义

大模型"深度研究"类应用常见的两条工程路线各有缺口：直接调用商业 Agent 产品，过程不可观察、不可恢复、不可审计；自行拼装多角色提示词脚本，则普遍缺少真正的图结构控制流、持久化与人工介入点。

本项目把问题定义为：**构建一个可观察、可恢复、可审计的多智能体研究工作台**，并显式回答三个工程问题——

1. 多角色的条件路由如何用受控的图结构表达，而不是一串 if-else？
2. 长时间任务在进程崩溃后如何从真实检查点恢复，且不重复计费、不伪造结果？
3. 如何在工程演示与真实模型实验之间保持诚实的证据边界？

## 2. 系统设计

### 2.1 总体结构

独立 FastAPI 服务（默认端口 8811），LangGraph `StateGraph` 驱动规划（planner）→ 检索（searcher）→ 分析（analyst）→ 审查（reviewer）四个角色；条件边由 reviewer 的结构化输出（`finish / search_more / revise / clarify`）直接控制；`web/` 为无构建步骤的中文工作台，通过 SSE 订阅真实事件流。

### 2.2 关键设计决策

| 决策 | 备选方案 | 选择理由 |
|---|---|---|
| 持久化用两个 SQLite 文件（任务账本 + LangGraph `SqliteSaver` 检查点） | 单文件 / 内存 | 任务元数据与图状态的生命周期不同；官方 checkpointer 保证恢复语义，不自研序列化 |
| 人工审核用 `interrupt()` + `Command(resume=...)` | 轮询 / 前端模拟 | 中断节点恢复时会重跑，因此中断前不调用模型、不产生费用——把成本安全做成框架语义而非约定 |
| 工具调用默认 JSON 模式，native 模式显式开启 | 只做一种 | JSON 模式兼容无 function-calling 的接口；native 模式按 OpenAI / Anthropic 各自原生协议实现（`tools/tool_calls` 与 `tool_use/tool_result`），不冒充 |
| 密钥仅存后端内存，数据库只存不可逆 hash | 加密落盘 | 本地单用户工具的威胁模型下，"重启后重填"是可接受代价，换取泄露面最小化 |
| 模型请求出网做 DNS 全答案校验 + IP 固定连接，禁私网/回环地址，禁跟随重定向 | 仅依赖 HTTPS | 防 DNS 重绑定与 SSRF；本地开发环境常配代理，显式禁止代理绕过 |

### 2.3 角色契约

底层可以共用一个模型，但每个角色有独立的输入、JSON 契约与执行权限：模型只提出搜索词，实际检索由受限搜索适配执行；外部片段放入 `external_sources` 字段并在系统指令中声明为不可信数据。应用本身没有任意工具调用、shell 或本地文件读取能力。

## 3. 引用核验的实际范围

报告必须引用输入来源编号，程序独立检查：引用是否存在、编号是否映射到真实来源。不存在的 `[99]` 会覆盖模型的"通过"判断并强制返工。

三个标志的语义被刻意区分：`all_mapped=true` 表示编号映射通过；`retrieval_verified=true` 只表示资料确实来自当前搜索响应；`claim_truth_verified=false` 恒为真提醒——**逐项事实真伪没有任何自动验证**。高风险研究仍需人工核验原文。

## 4. 测试与验证策略

测试隔离由 `tests/isolation.py` 提供：导入应用前清理全部密钥与代理环境、默认阻断未注册的外部连接；真实联网测试独立命名、显式 opt-in，不进默认 `pytest` 与 CI。覆盖面包括：

- 多供应商模型 CRUD、OpenAI / Anthropic 原生协议与工具循环、错误分类与回显秘密清洗；
- cookie / 模型 / 任务 / SSE / 导出 / benchmark 的 owner 隔离；
- 两类真实进程恢复测试：暂停后跨进程恢复；分析节点运行中强制 kill 后从检索后检查点继续且不重复已完成节点；
- 统计一致性：五类 usage 夹具（带 usage / 无 usage / 429 后成功 / 缓存 token / 超时），未知费用不得显示为免费。

GitHub Actions 在 Windows / Ubuntu 的 Python 3.12 上运行核心测试。

## 5. 公平对照实验框架（A08）

`scripts/prepare_experiment.py` 生成可重放实验计划：15 题 × single/multi × 2 次重复 = 60 执行单元，带 dataset/prompt 哈希、代码 HEAD 与 dirty 状态、冻结配置与检索缓存 schema；执行顺序按 seed 随机化，两架构交替出现。质量量表（5 维度 × 1-5 分）规定由**独立人工复核**评分，明确禁止 Agent 自审。

## 6. 证据边界声明

当前全部验证基于离线演示与注入 `httpx.MockTransport` 的协议夹具；真实供应商小预算验收（A10）与真实 single/multi 对照（A11）状态为 `awaiting_live_authorization`。**本地协议夹具通过不构成对任何供应商实际可用性或模型能力的断言**；mock 汇总不生成"准确率"或"多 Agent 更优"的结论。用户在网页配置自己的密钥后即可执行真实验收。
